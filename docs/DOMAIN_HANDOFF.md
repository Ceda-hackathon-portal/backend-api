# Domain schema and service contract for joint review

Status: proposed, 18 November. No domain migration or public domain route exists. A integrates migrations; B owns policy and workflow. Review against B's 2e0d3b1 before authorizing SQL. Initial delivery is one programme, submission, preliminary check and independent officer review.

## Proposed first migration

Each table has a UUID primary key named id. Times are timestamptz in UTC. FK deletion is restricted. Fields below are required unless marked ?. Use existing users.id and sessions.id. Proposed short codes are text validated against the reviewed finite sets. UQ means unique constraint. Published configuration, submissions, assessments, reviews and events are append-only to the runtime DB role. Use separate owner/migration credentials. Enforce immutability with restricted privileges and database triggers, including dependent configuration rows.

## HTTP and policy boundary

Proposed POST /api/v1/eligibility/screen accepts exactly {programmeId, programmeVersionId, applicantEvidence:[{requirementKey,value}]} with a boolean tagged value or decimal string plus unit. Reject unknown properties, duplicate evidence identifiers, unknown requirement keys and malformed decimals with 422. Multiple separately sourced facts for one key can conflict. Load the matching published configuration on the server; clients cannot select thresholds, sources deemed verified, reviewers or grants. Proposed authenticated preflight is preliminary and transient: no application/version is in this request. On submission independently repeat screening against the immutable version and persist that result. Do not create orphan checks.

Return {data:{programmeVersionId,overallStatus,findings:[{requirementKey,status,reasonCode?,unknownReason?}],requiresOfficerReview:true,isFinalDecision:false}}. Map requirementKey through the ruleset to B's requirementId, assign internal evidence IDs, map assessment.status to overallStatus and map findings back to keys. Do not infer verification from a boolean. Distinguish MISSING, CONFLICT, UNVERIFIED, INVALID and VERIFIER_UNAVAILABLE in the proposed adapter contract. Invalid HTTP shape returns 422; unusable evidence from an authorized external source yields UNKNOWN. CONFLICT and missing/unavailable evidence cannot cause final rejection. Automated assessment never creates an officer review.

B's published types use boolean/number/null evidence, attestation and gte/lte rules, and only MISSING/CONFLICT unknown reasons. Strict gt and unit-bearing decimals are unsupported. Proposed decimal contract: canonical strings, unit per published requirement, scale at most six, reject excess precision without rounding; exact scaled integer comparison or decimal arithmetic, no conversion to JS Number. For a configured gt 50 percent rule test 49.999999, 50, 50.000001 and mismatched units. Do not translate gt to gte. B must approve public type/operator evolution or a separate exact comparator interface. Agree precedence when different sources are invalid/unverified/conflicting.

## Proposed service interfaces and transaction ownership

| Interface | Input and result | Enforcement |
|---|---|---|
| principal / authorize | Existing Principal {userId,sessionId,authnLevel}; access {permission,programmeId,recordId?} | A supplies trusted live reader; recheck session, grant, assignment and revision in write transaction. |
| publishedProgramme | (programmeId,programmeVersionId) -> pinned ruleset, requirements, criteria, intake window | A loads exact published pair, never mutable fixtures. |
| submit | (principal,applicationId,expectedRevision,idempotencyKey) -> reference, versionId, revision | A checks owner and deadline, locks application, snapshots fields, inserts command receipt/history/audit/outbox atomically. |
| assess | (requirements,evidence) -> EligibilityAssessment | B owns both pure functions. Invoke locally inside submission transaction for persisted screening; external verification is a separate input or asynchronous step. |
| verifyOfficer | (principal,checkId,expectedRevision,decision,reason,evidenceIds,conflictResolution?,idempotencyKey) -> reviewId,stage,revision | Load version-bound evidence, require current programme permission and separate human decision; transactionally append review/history/audit/outbox. |
| allowedActions / transition | (principal,applicationId) -> allowed action codes; command includes action,revision,reason | B owns transitions. Recheck on write; concurrency loser gets 409. Applicant receives released/owner-safe history only. |
| assignmentAccess | (principal,assignmentId,versionId) -> own permitted scorecard | Future assignment(application,version,stageRun,reviewer), conflict(assignment,declarer,status,time). Current active, conflict-cleared assignment required; revoked/unresolved denies. |
| finalizeScores | (principal,assignmentId,criteriaVersion,expectedRevision,decimalScores) -> locked evaluation | Future criterion(programmeVersion,key,unit,range,weight), evaluation(assignment,lockedAt), score(evaluation,criterion,value). UQ score pair. Agree rounding, quorum, evaluator isolation and revision effects. |
| decide / release | (principal,applicationId,versionId,revision,outcome,reason,key) -> decisionId; release(decisionId,revision,key) -> feedbackId | Future decision pins closed score set; feedback pins decision and release actor/time. Separate permission and serializers. |
| appendAudit / enqueue | (tx,actor,action,target,requestId,eventId); (tx,auditId,kind,recipientId) | A supplies shared transaction-scoped writers. B supplies event semantics. No remote calls before commit. |

## Joint approval requested

A and B confirm rule IDs, evidence source/verification vocabulary, decimal scale and strict operators, preflight persistence boundary, evidence retention, multi-review/supersession rules, capability names and correction/score invalidation. Frontend owner confirms CSRF and origin flow plus version, receipt and status DTOs. Until agreement, keep routes unmounted. The first integration acceptance test creates a draft, submits once under concurrent retry, denies another applicant/programme, records preliminary findings, permits only a scoped officer to confirm, and verifies audit/history rollback on failure.
